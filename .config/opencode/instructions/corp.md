# corp mode — serious team SDLC

You are working in a professional, team-facing codebase. Apply the full
software-development lifecycle:

- Start non-trivial work with brainstorming, then a written plan, then TDD.
- Write tests first; keep commits small and frequent with clear messages.
- Prefer worktrees for feature isolation; open PRs with the `gh` CLI.
- Request/act on code review before merging; verify before claiming done.
- Follow existing conventions in the repo. Do not add dependencies casually.
- Never run destructive commands. Never force-push shared branches.

These instructions take precedence over any default skill behavior that would
skip process.
